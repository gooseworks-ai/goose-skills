# GooseWorks Next skills

This is a separate preview for the rebuilt GooseWorks app. It contains all 16 guides, their references, the connector settings and ready-to-install plugin archives. The current GoSkills catalog and its CLI installation stay unchanged.

## Install the preview

Use this branch's files; these files are not part of the current catalog release.

- **Claude:** import [the Claude plugin archive](downloads/gooseworks-next-claude.zip) into a host that supports Claude plugins. For a local Claude Code session, run `claude --plugin-dir /absolute/path/to/this-checkout/rebuild/plugin`.
- **Agent Plugins:** import [the Agent Plugins archive](downloads/gooseworks-next-agent-plugins.zip) into a host supporting that plugin format. It includes the plugin card, icon and streamable HTTP connector.

The plugin is **GooseWorks Next** (`gooseworks-next`) and connects only to `https://mcp.gooseworks.sh/mcp`. Sign in through that connector's normal consent flow. Choose this preview explicitly when the old GooseWorks plugin is also installed. Do not copy these guides over the current `gooseworks` entry skill or use the current CLI's catalog installer to install this preview.

These are the rebuild's guides and tool contracts. The old app's connector cannot run them. The matching backend changes must be deployed through their own approved release before all corrected flows are available. This PR does not publish the catalog, install anything globally, or deploy the backend.

## What the guides cover

[skills.json](skills.json) is the generated guide index with descriptions and steps. It routes brand setup and Brain upkeep, competitor research including video ads, image ads and variations, video planning and making, files, social inspiration, creative review, campaigns and Meta results.

- Suggestions stay suggested until the person chooses Watch. Watching activates the saved competitor and follows its queued research.
- Software and services can make supported conceptual image ads without product photos. Physical products still need real photos. Video rows follow their style's asset checks; no invented app interfaces or customer quotes.
- Prices and claims come from the brand's approved facts. A credit charge needs approval on its quote card or page; a typed yes does not spend credits.
- Connected Meta accounts receive reports and suggestions on the server. The guides read the saved reports with their dates and account context. Account changes are made by the person in Ads Manager. Finished ads export as a pack; the connector never launches, pauses or changes Meta ads.
- Every answer's `nextStep` controls what happens next. The guides do not use an old tool adapter or approve charges or account changes on the person’s behalf.

## Source and updates

The only authored source is the rebuilt app repository: skill bodies and manifests live under `apps/plugin/gooseworks`, reference masters under `apps/plugin/references`, and the connector’s shared rules and tool contracts under `apps/mcp`. Edit the owning source there, run `pnpm --filter @gooseworks/plugin write-skills` when references or shared rules change, review the result against the connector, commit it, then export it here. Do not edit `plugin/`, `downloads/`, `skills.json`, `tool-contract.json` or `source.lock.json` by hand.

[source.lock.json](source.lock.json) pins the full source commit and hashes every generated file. [tool-contract.json](tool-contract.json) records the input schemas for the 67 customer tools these guides reference, plus shared rules from the same build. It is not the full MCP tool catalog. The export uses the app's official `team` plugin builder; it does not maintain another packager or handwritten router.

With a clean checkout of the private app repository at the pinned commit and its dependencies already installed, run from this repository:

```sh
node rebuild/scripts/sync.mjs --source /absolute/path/to/new-app --ref FULL_SOURCE_COMMIT
node rebuild/scripts/verify.mjs --base FULL_GOSKILLS_BASE_COMMIT
node rebuild/scripts/sync.mjs --source /absolute/path/to/new-app --ref FULL_SOURCE_COMMIT --check
```

The full source commit is in the lock file; use the PR's exact base commit for the GoSkills base. The source checkout must have no uncommitted files. Exporting runs the app's own tool-contract generation, guide checks and official plugin build. `--check` rebuilds from that exact commit and compares all generated bytes, including the install archives.

The standalone CI checks the generated file inventory and hashes, manifests, new connector address, every named tool, shared rules, sibling guides and packaged links. It also refuses any change outside `rebuild/` and its dedicated workflow relative to the PR base. The current catalog's own CI still runs separately.

The app repository is private. This public repository's default CI token cannot read it, so offline checks cannot prove agreement with upstream. Run the authenticated source comparison above for that proof; do not describe offline hashes as an upstream freshness check. A future source change needs another reviewed export.

Do not merge or publish this preview with the backend or CLI work. It stays a separate draft PR until the owner approves its release.
