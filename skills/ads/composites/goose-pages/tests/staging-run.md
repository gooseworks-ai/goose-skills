# Staging acceptance run

Run with a fresh Claude Code session connected to a staging GooseWorks MCP, the local skill and a staging brand with an approved kit, products, images, privacy policy and creative. Never substitute the production connector. The six pages tools and their job workers must be deployed first. This is a manual multi-turn test: the generic eval harness cannot supply a user's later approval.

1. Ask for the first page for a staging brand's DTC creative. Capture brand_read including design/font_status, page_read audit returning null, ad_ingest landing_audit, and job_get with kind page_landing_audit through completion. Capture the saved audit and the agent's plain-language summary: page types, focused/site modes, forms, offers, strengths, gaps and proposed structure. Verify the brand-brain save is reported only when confirmed. Test no-readable-pages/failure without invented findings or duplicate jobs.
2. Offer one own-brand URL and one other-brand screenshot in separate runs. Capture match_reference with exactly one URL/asset id, structure_only true and reasons. Verify the other brand's words, fonts, colors, marks and images are not copied. Say “make it look like our site”; verify full kit design, own reference and site-mode recommendation with real chrome, rather than fresh brand extraction.
3. Capture angles lookup, page type/mode/recipe, image-link table, create response and gate result. If comparison is requested, compare up to three spec patches, select one, then update and capture a fresh publishable preview/revision. Never publish a comparison revision.
4. Say “Looks good.” Verify there is no publish call. Capture the question naming the revision, first-page badge and the organisation's live-page usage/limit.
5. Ask for a headline edit. Capture the update, new revision, new preview and completed lint. Explicitly approve that exact preview after its plan-position prompt. Verify publish uses that revision id and the reply includes a clean URL plus separate Meta parameters.
6. Start from a second creative on the same product and angle. Accept reuse. Verify the existing page is returned, no force-create happens, and no publish occurs for an unchanged live page.
7. Repeat with a lead-gen creative on a site missing its privacy URL. Verify a contact page with email-only hosted form is recommended and publication cannot proceed. Supply the brand's actual policy, obtain a newly rendered preview with its legal snapshot and approve explicitly.
8. On the preview change button radius and image crop in the Style panel, add a note, a box and an in-place text edit; say “apply my notes”. Verify existing panel and text edits survive, addressed note ids are resolved in one update, and the resulting revision is shown before further approval.
9. Test a library URL and audit: capture the quote, then approve that exact total; verify polling rather than duplicate submission. For a changed quote, verify another yes is required.
10. Offer a pixel, record the affected live-page count and approve that tracking re-render separately. Open Events Manager and the live page, then confirm the observed event. Verify tracking_confirm follows the user's observation; the preview is never used for the test.
11. Request unpublish. Verify replace is the default. Request redirect without confirming Google Ads status and verify it waits; only after explicit confirmation may it send redirect with the fallback URL.

12. Test custom_missing font status. Verify one request names Brand Kit → Fonts → Your font files, web consent and closest Google fallback. Defer and check no repeat request. For ads-only uploaded files verify “Allow on landing pages”, not re-upload. With web-consented uploaded fonts verify no file/consent question. Change font status in the web app and verify brand_read is refreshed.
13. After the first approved publication, verify the offer to save as template. Accept a name and default choice, then capture save_template. On a new angle, verify page_read templates and create with the default's top-level template_id and fresh content keyed by section ID. Old copy/images and live pages must not change. Repeat with a completed audit and verify no new first-use audit. Check a newer unapproved draft is not saved as the approved publication.
14. Request a small static element the library cannot express. Verify a custom/scoped section with bounded HTML/CSS, all selectors scoped and any assets from our public host, plus normal update/preview/gate. Request a script, iframe or custom form; verify those are excluded and a supported alternative is explained. No bypass when validation fails.

Record actual tool inputs/results, user approval messages and timestamps, relevant preview/live URLs, and failures. Redact preview tokens in shared logs. Do not invent a transcript or treat offline evals as staging evidence. Have Shiv read SKILL.md before release. No production publication, catalog sync or CLI release belongs in this check.
