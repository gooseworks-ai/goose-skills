# Engine notes — how the render tool behaves (gooseworks-app, 19 Oct 2026)

Load at Steps 1, 8 and 10. These shape the method; the live tool answers are the truth for parameters.

**In short:** `ads_render` is a thin tool — it sends the agent's prompt and images to the image model word for word and does nothing else. So everything the server's pipeline does around the image model, the agent does itself, from the server's own copied text: compose (`composer.md`), font specimen (`font-specimen.md`), blueprint (`structure-blueprint.md`) and judge with one retry (`judge.md`).

- **Research first.** Rendering needs the brand's research complete (`brand_read` → `research_status: "complete"`); otherwise it fails after the yes. `running` → wait (`gooseworks:job_get` `kind: "brand_research"`) or come back; `none` → the brand isn't set up yet (say so in plain words; setup is a separate job); a brand with no website or store link can't complete research → images can't be made yet: offer the concepts, templates and copy as a copy-only deliverable.
- **Read sizes.** For Steps 1–5 read summary, kit, products and competitors lean (with `product_ids`); a lean read already returns every `must` and `dont` learning. For compose, read the kit and learnings in full **once per batch** (`composer.md` §1 — the kit is very large; a shell host saves it and reads fields with `jq`). Never `detail: "full"` on every section at once.
- **The thin render tool** (`gooseworks:ads_render`, gooseworks-app PR #2105). It sends the `prompt` and the `image_urls` (public https, in order) to the image model verbatim: no template, no kit images, no font specimen, no prompt writer, no judge, no retry, no fallback. The result is an ordinary creative with a quote. Ratios: `1:1`, `4:5`, `9:16`, `16:9`, `3:4`. One call per distinct base prompt (`composer.md` §11) — in practice one per ad and ratio; `variants: 1` always.
- **What the agent must therefore supply:** the composed prompt and image list (`composer.md`), the font specimen when eligible (`font-specimen.md`), the blueprint for every template the brand doesn't own (`structure-blueprint.md`), and the judge with one retry (`judge.md`). The server pays for its own retries; here every retry is a paid render, so the Step 8 yes covers one retry per image at the same price, said up front.
- **Structure-only follows ownership.** Imported competitor ads, library and community templates are structure-only on the server. A Meta ad registered with `ads_template_create` is saved as an upload, which the server would remix from its pixels (server-needs N0) — this playbook treats every registered ad of another brand as structure-only itself (`atoms/find-references/ATOM.md` step 6).
- **Fonts.** The kit always returns a font, often one the server guessed (`typography.source: "mapped"`), and Inter for many software, finance and services brands. On `competitor_scrape` and `curated` templates the composer forces brand font and colours on (`composer.md` §2.1). A brand font that resolves to a plain system face for a designed headline → the typography improvement in `atoms/compose/ATOM.md`.
- **Layer split.** `ads_creative_edit` `action: "layerize"` takes about two minutes, returns transparent background, image, logo and text layers with positions, and has no dry-run price — tell the marketer it costs credits and get their yes first.
- **Edits are unquoted.** `regenerate`, `precision_edit` and `resize` return no dry-run price, so they are not used. Every remake, text fix, extra placement and copy variant is a composed, quoted `ads_render` call (copy variants may also use layerize).
- **List reads are heavy.** An unfiltered `ads_creative_read` carries video plans and can be very large — always filter (`approved_only`, `tags`, `batch_id`) with a small `limit`.
- **Tags.** `ads_creative_update` `patch.tags` now saves to the creative's `user_tags` (fixed in gooseworks-app PR #2105). Tags replace the whole set and are stored lower-case: read the current tags, merge, write the full set once; write and query lower-case (`angle:a-07`). Picks also go in the batch file.
- **Campaign records are input only.** `campaign_read` gives an approved campaign's brief and concepts (use them only when the brief's Status line says "Approved"); this playbook never generates through the campaign tools.

- **Polling.** `job_get` (`kind: "ads_batch"`) reports the batch `status` as `complete` when done and each creative's `pending` count; stop when every `pending` is 0.
- **Saving an agent-made image.** `ads_save` turns an image already uploaded with `media_upload` into an ordinary ad creative (one complete render, linked to its parent with `parent_creative_id`). Free: no model runs, no credits. Use it for layer-method copy variants and any image the agent finished itself.
