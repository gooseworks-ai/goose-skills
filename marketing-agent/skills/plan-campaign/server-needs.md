# plan-campaign — server needs

What the playbook needs that the GooseWorks MCP does not have today (checked against staging, 2026-10-16), which step needs it, and what the playbook does meanwhile.

| # | Need | Step | Meanwhile |
|---|---|---|---|
| 1 | **Business-context store in the brand brain**: margin / contribution per order or per SKU, AOV, repeat rate, LTV, budget and what is committed, the number marketing owns + target + date, list size, capacity. No `brand_update` field holds these (kit/knowledge fields are positioning, audience, voice; facts are learnings). | Before you start (5), step 2 | Asked each time it is missing; kept in the brief's Economics and Status sections on the campaign record. Re-read from the latest brief next run. |
| 2 | **Stock levels** per SKU (and inbound) — product records carry name, price, photos, variants; no stock. | Step 2 (capacity check), replan triggers | Asked for featured SKUs. |
| 3 | **Campaign channels beyond `paid_social`** — `campaign_upsert.channels` accepts only `paid_social`. The channel decision covers ~12+ channels. | Write-back | Full channel decision lives in `brief_md`; `channels` set to `paid_social` only when a paid social leg is Run/Test (left empty otherwise). |
| 4 | **Structured campaign fields for targets and tests** — `goal_target` is deprecated; there is no field for per-leg targets, the economics box, test success criteria or replan triggers. Siblings must parse the brief's headings. | Write-back; read by run-paid-campaigns and analyze-performance | Fixed headings in `brief_md` (see `references/brief-template.md`) as the contract. Ask: structured `targets`, `tests[]`, `economics` on the campaign. |
| 5 | **Asset list as a structured object** the makers can consume (rows with spec, angle, claim id, due date, producer). Concepts cover only paid static/video ideas. | Step 7, hand-off to makers | Asset list table in `brief_md`; paid static/video angles also saved as campaign concepts. |
| 6 | **Brief edit without discarding pending creative plans** — any non-status `campaign_upsert` discards plans awaiting a yes. | Write-back, replan | Check `ads_creative_read view: approvals` first; ask the human before saving over pending plans. |
| 7 | **Account-level current numbers** for replan (all Meta campaigns, Google, etc.), not only Goose creatives. | Replan mode | Read analyze-performance's weekly reads, which carry human-provided totals. |
| 8 | **Promo / seasonal calendar** as a brand-brain object (pillar 18). | Step 1, collisions | Asked; written into the brief's Calendar. |
| 9 | **Where analyze-performance's reports and run-paid-campaigns' change log live** — no first-class object; this set uses workspace files in the brand's coworker workspace (`reports/performance/…`, `ads/campaigns/<slug>/decisions.md`). | Replan mode | `file_list` / `file_read` with scope `{type: agent, agent_id: <brand's coworker_agent_id>}`. Confirm this is the intended home. |
| 10 | **Monthly replan schedule** — `automation_upsert` agent mode exists, but its credit cost per run is not shown up front. | Output (recurring offer) | Offered once; created only on the human's explicit yes after stating that runs use credits. |
| 11 | **One definition of "approved claim"** — the server's `kit.approvedClaims` / `knowledge_search [claim]` marks research-found press quotes as "approved" (all 7 on Personal Day, applicability `unknown`), while the claims gate's sign-off (marker + "Claims you may use" `must` facts + dated Brand record) is the owner's approval. Concept `proof` validates against the server's list. | Angles, concepts | Approved = the claims gate's sign-off; concept proof only when the claim is in both. Raise with the orchestrator / server owners. |
| 12 | **Claim applicability** — claims arrive with `unknown` applicability and are refused as concept proof. | Concepts | Proof left empty, gap named; the claims gate's scoped sign-off records scope. |
| 13 | **No maker for search ad copy, keyword lists or PDP/landing copy** — make-content and make-static-ads exclude them. | Hand-offs, Google leg | Human-executed; brief asset row carries angle, searcher words, signed-off claims; run-paid Google card uses the confirmed copy. Consolidation pass should assign a producer. |
| 14 | **A durable link to a brand document** — `file_url` returns a presigned download URL that expires after ~1 hour, so "Saved to your brand: [open]" breaks the same day (write-report §2.3). | Delivery | The closing line says the plan is also in the brand's documents; ask: a stable app link to a workspace file or brand document. |
