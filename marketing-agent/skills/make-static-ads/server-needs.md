# make-static-ads — server needs

What this playbook needs that the GooseWorks MCP does not give today. Each: the need · the step · what the playbook does meanwhile.

**Status in short (v0.4, 19 Oct 2026):** the thin render tool shipped (N1, gooseworks-app PR #2105) and tag writes were fixed in the same PR (#21). Per-ad copy direction (N2) is solved inside the composer's Variant brief. Still open and most important: other brands' ads registered as templates must be structure-only on the server (N0). New since the composer port: N13–N17. Items 1–21 were checked against staging on 2026-10-16 and describe the earlier route through the server's own prompt writer; they are kept for history, with their status updated.

## Added 2026-10-19 — concepts, templates, the composer port

### High

N0. **Structure-only must follow rights, not only source kind.** — **Open.** The pipeline decides "structure only" from the template's source kind (competitor import, community, curated); `ads_template_create` always saves kind "upload" and `rights_attested` is stored but never read, so another brand's ad registered with `rights_attested: false` would be remixed from its **pixels** by the server. *Step 4.* Meanwhile: this playbook registers Meta ads it finds (`references/references-and-remix.md` §4) and treats every registered ad of another brand as structure-only itself — it writes the blueprint and never puts the image in an `ads_render` image list (the `make-static-ads-find-references` skill (`../make-static-ads-find-references/SKILL.md`) step 6). Ask: `ads_template_create` from another brand's ad (or with `rights_attested: false`) saves a structure-only template.
N1. **Send the agent's prompt to the image model word for word, with a quote.** — **Done: `ads_render`** (gooseworks-app PR #2105). The playbook composes and judges itself (`references/composer.md`, `references/judge.md`) and renders through it. No fallback route remains.
N2. **Per-ad copy direction.** — **Resolved in the playbook.** The composer's own Variant brief slot (`references/composer.md` §6.7, the server's `variant_briefs` form) carries each ad's concept, so no server change is needed for `ads_render`. The app's batch path still does not expose `variant_briefs` to callers; that matters only for the app, not this playbook.
N3. **A static references finder, like the video one.** Video gets `video_references` `find` (free to the customer, Meta + TikTok + Instagram, ranked by fit × days running, shown as a "Use this" card, `pick` starts the project). Statics have nothing: the template library ranks the same templates first for a brand every time, and competitor imports cover only tracked competitors. *Step 4.* Meanwhile: `make-static-ads-find-references` — own and competitor imports, category leaders' Ad Library pages by eye, the paid proxy for gaps, a self-built gallery, registering picked Meta ads with `ads_template_create` and running them structure-only. Ask: `static_references find` / `pick` (same ranking as video, `media_type` image/DCO/carousel, category leaders as well as competitors, platform-funded), with a card whose button registers the pick as a structure-only template.
N4. **Lean ad-library reads for chat hosts.** One `/v1/facebook/adLibrary/search/ads` call returned 724 KB for 30 ads; `company/ads` 172 KB for 29. A chat host without a shell cannot hold that. *Step 4.* Meanwhile: shell hosts filter the saved result; chat hosts use the free paths and the host browser. Ask: a `fields` filter on the proxy, or N3.

### Medium

N5. **Layer split has no price.** `ads_creative_edit` `layerize` takes ~90–145 s, bills fal cost +30% and has no `dry_run` quote. *Step 11.* Meanwhile: told it costs credits, run only on the marketer's yes, never in a batch.
N6. **Fonts fall back to Inter, and the font flags are ignored on most sources.** The kit always returns a font, often a guess (`typography.source: "mapped"`); on competitor and library templates the composer forces the kit font and colours on (`effectiveStylingFlags`), so `apply_brand_font: false` has no effect there. With no brand font, software, finance and service brands get Inter, and an alias table maps SF Pro, Segoe, Geist, Satoshi and others to Inter. *Steps 2, 6.* Meanwhile: when the font resolves to a plain system face for a designed headline, the marketer picks a Google Fonts pairing and the agent uses it in the Typography line and the specimen (the `make-static-ads-compose` skill (`../make-static-ads-compose/SKILL.md`)). Ask: honour the flags (or warn), curated display faces per brand type in the server's font library, Inter only for native UI frames.
N7. **No diversity in template choice.** `static_library` without a query is deterministic (tag overlap + a brand boost), and with a query it is pure similarity; nothing spreads a batch across frameworks or looks. *Step 4.* Meanwhile: the agent picks references per concept slot. Ask: diversity-aware ranking (e.g. maximal marginal relevance) when several concepts are filled at once.
N8. **Template detail does not show the layout blueprint the server would use.** The agent extracts its own blueprint with the server's prompt (`references/structure-blueprint.md`), so its blueprint and the server's can differ run to run. *Step 6.* Meanwhile: extract once per template per batch, in a fresh subagent where possible, and keep it in the batch file. Ask: see N14.
N9. **`company/ads` with `media_type: "IMAGE"` returned nothing for AG1** while `"all"` returned 29 ads, most of them DCO and image statics. *Step 4.* Meanwhile: `"all"` and filter on `snapshot.display_format`.

N10. **Exact text as a launchable creative.** — **Dropped (v0.4).** The playbook no longer sets text or builds images in code; the image model draws the text from the composed prompt, with the font specimen. Copy variants made by the layers method are uploaded to the media library and flagged "launch depends on the push taking a library image".

N11. **`mode: "mine"` mixes uploads with the brand's own Meta ads,** including other brands' reference images, and repeats one ad per version (~3 KB a row). *Step 1.* Meanwhile: keep `source_kind: "scraped_meta"`, merge by primary text, small `limit`. Ask: a source filter and one row per ad.
N12. **The brand-brain tools.** — **In use.** `brain_map`, `brain_search` and `brain_open` give each fact a status (`confirmed`, `found`, `guess`, `unknown`); Step 1 and the claims rule read them (`references/reading-the-brain.md` §1). On a server without them, the kit's proof points and value props and the product record count as `found`.

### New with the composer port (19 Oct 2026)

N13. **Run the server's judge, with a free retry, from `ads_render`.** The agent judges its own renders with the server's rubric (`references/judge.md`), but it is not the server's strict, separate judge, and every retry is a paid render (the server pays for its own). *Step 10.* Meanwhile: a fresh subagent judges; the Step 8 yes covers one retry per image at the same price. Ask: an `ads_render` option `judge: true` that runs `judgeRenderImage` against a supplied target (template or blueprint, references) and retries once with the server's note at GooseWorks' cost, returning the checklist.
N14. **A server-side blueprint tool.** The structure-only blueprint is extracted by the agent, who also composes, so the isolation the server keeps is only approximated (subagent or self-check). *Step 6.* Ask: `ads_template_read` returns (or a `template_blueprint` tool extracts) the server's blueprint for a template, so the agent never views another brand's ad at all.
N15. **Font specimen on the server, or signed access to uploaded brand fonts.** The server prefers the brand's uploaded font file; no MCP read returns it, so brands with a custom font get no specimen from the agent (`references/font-specimen.md`). *Step 6.* Ask: a tool that renders the server's specimen for given lines, or a signed URL for the brand's uploaded font files.
N16. **The current recurring-rejection rules.** The server recomputes the brand's recurring-rejection directives live; the agent can read only the stored summary learning (`references/composer.md` §6.5, §12). *Step 6.* Ask: return the live directives in `brand_read` learnings.
N17. **`ads_template_create` from another brand's ad should save a structure-only template** — the same ask as N0, listed here because the composer port depends on it for every Meta ad the gallery registers.

## Checked 2026-10-16
## High

1. **Claim status reaching the claims path.** — *Superseded by the brain statuses (N12).* Research auto-creates claims as "approved" from the website and press; product-scoped search turns them `approved_scope_unknown`; the server's own hint calls kit proof points claim-grade (Personal Day's include press quotes about a mist and a toner). No tool changes a claim's status. *Steps 1, 7.* Now: the brain status rule (`references/claims-and-policy.md` §2).
2. **One quote for a multi-ad set.** `ads_render` takes one prompt per call (one per ad and ratio), so a ten-ad set is many dry runs and submits, and the server forbids the agent's own sum. *Step 8.* Meanwhile: show each quote line as returned and ask for a yes to "these N quotes". Ask: a batch dry run (several prompts) that returns one total, or a `prompts[]` per source item.
3. **Dry-run prices for edits.** `ads_creative_edit` `dry_run` prices only `animate`; `regenerate`, `precision_edit`, `resize` cannot be quoted. *Step 10.* Meanwhile: retries, fixes, extra placements and copy variants as composed, quoted `ads_render` calls; `regenerate`, `precision_edit` and `resize` not used until their dry run returns credits (`ads_creative_edit` is in `needs.mcp` for `layerize` only — copy-variants, on a yes).
4. **Dry run that validates what the submit requires.** A brand with `research_status: "none"` gets a quote, then the submit fails ("needs a brand with completed research"). *Before you start, Step 8.* Meanwhile: check `research_status` first.
5. **Lean creative list.** Unfiltered `ads_creative_read` returned 2.1 MB for 17 creatives (video script drafts in every row). *Step 1.* Meanwhile: only filtered reads with a small `limit`. Ask: a lean list mode and a format filter (static / video).
6. **Text-read of rendered ad images.** Product photos and video renders are analysable with `media_analyze`; it is unconfirmed whether ad renders are registered assets. Chat hosts that cannot see images need the drawn text for claims Pass B. *Step 10.* Meanwhile: look when the host can; otherwise "not visually checked" + checklist.
7. **Agent-proposed learnings are refused.** `brand_update` `facts` needs `user_correction` + the human's statement, so lessons the agent observed (a template that imports a seal, a disapproval cause) cannot be proposed for review. *Write-back.* Meanwhile: offer each lesson; save only on the human's yes, in their words.
8. **Screenshot compositing.** A screenshot passed as `reference_image_urls` is redrawn, so B2B UI ads risk fabricated product UI. *Step 6, formats §2.* Meanwhile: letter-by-letter check against the real screenshot, else drop; default B2B to text-native archetypes. Ask: a "place this image unaltered" mode.

19. **Campaign concepts need server-visible proof.** — *No longer used here:* v0.4 reads campaign records as input only and never generates through them.
20. **Brand reads are huge.** `brand_read` with `detail: "full"` on several sections plus `product_ids` returned ~249,000 characters (a ~130,000-character `brand_context` bundle). *Step 1.* Meanwhile: lean reads, learnings alone in full. Ask: `brand_context` only on request.

21. **Tag writes may not reach the server (cross-set review F5a).** — **Fixed in gooseworks-app PR #2105** (`tags` now saved as `user_tags`). By code reading, `ads_creative_update` sends `{ tags }` to a strict schema whose field is `user_tags`, so tag writes may be rejected; tags that do save are lower-cased. *Steps 10–12, gate 4.* **Status: unverified** — the staging write test (write `["angle:A-07","picked"]`, read back with `tags: ["angle:a-07"]`) was blocked by this session's permission guard on 2026-10-16. Meanwhile: tags written lower-case; picks, angles and the manifest also live in the batch file, which is the record of truth. If the test confirms the rejection, it is a gooseworks-app bug: map `tags` → `user_tags`.

## Medium

9. **Template detail in list rows.** `remix_spec` (which can order claims onto the image: "reset the handwritten testimonial to the brand's claim") and a similarity floor are not in list results; off-category matches come back for notes-app / stat-card queries. *Step 4.* Meanwhile: read each candidate's detail; treat similarity below ~0.45 as no match.
10. **Live stock and a currency on price.** No stock field; price is "16.00" with no currency. *Steps 2, 12.* Meanwhile: ask.
11. **Performance for ads Goose did not make, and frequency.** `meta_read` covers Goose-made creatives only and returns no frequency. *Steps 1, 3.* Meanwhile: own scraped ads' run length as a weak signal; rotation reasons taken from run-paid-campaigns' request.
12. **Structured offers.** Free-text `offers`; no code, terms or end date; sources disagree (free shipping $45+ in claims, $39+ in the brand's Google ad). *Steps 2, 7.* Meanwhile: ask; tag promo ads `offer-ends:`.
13. **Ratios** (no wider ratio or Pinterest target). `ads_render` offers 1:1, 4:5, 9:16, 16:9, 3:4 — no 1.91:1 or 2:3. Meanwhile: 16:9 for landscape, 3:4 for Pinterest, flagged (`references/formats-and-placements.md` §3).
14. **A "picked for launch" decision distinct from quality feedback.** The run decision rides on feedback `happy`, which also trains the quality loop. Meanwhile: `happy` only on the human's words, plus a `picked` tag.
15. **A structured batch manifest field.** Nice to have; meanwhile the batch file in the workspace (`ads/batches/…`) and the tags carry it.
